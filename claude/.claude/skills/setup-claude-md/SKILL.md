インタビュー形式でユーザーからプロジェクト情報を収集し、CLAUDE.mdを生成する。

## 全体の流れ

1. インタビュー実施（深掘りあり）
2. CLAUDE.md を生成（プロジェクトルート）
3. 詳細ファイルを空で生成（`.claude/` 配下）
4. 完了アナウンス

---

## フェーズ1: 事前調査

インタビュー開始前に、既存情報を収集してインタビューに活用する。

- プロジェクトルートの `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `composer.json` 等を確認して技術スタックを推測する
- 既存の `README.md` があれば読んでプロジェクト概要を把握する
- 既存の `CLAUDE.md` があれば内容を確認する（上書き前に確認を取る）

---

## フェーズ2: インタビュー

以下の項目をユーザーにインタビューする。各項目は**1問ずつ**聞き、回答を受けてから次の質問に進む。回答が曖昧・不十分な場合は深掘り質問をして詳細を引き出す。

### インタビュー項目

**1. プロジェクト名**
- 「このプロジェクトの名前を教えてください」
- 深掘り：package.json等で確認できる場合は「〇〇という名前で合っていますか？」と確認する

**2. プロジェクト概要**
- 「このプロジェクトは何をするものか、1〜2文で説明してください」
- 深掘り例：
  - 「主なユーザーは誰ですか？（個人利用 / チーム / エンドユーザー向けなど）」
  - 「プロジェクトの主な目的・解決したい課題は何ですか？」
  - 「現在のフェーズは？（開発中 / 運用中 / リニューアルなど）」

**3. 技術スタック**
- 「使用している言語・フレームワーク・主要ライブラリを教えてください」
- 事前調査で推測できた場合は「〇〇・〇〇を使っているようですが、合っていますか？他に重要なものがあれば教えてください」と聞く
- 深掘り例：
  - 「データベースは何を使っていますか？」
  - 「外部サービスやAPIに依存していますか？」
  - 「モノレポ構成ですか？それともシンプルな構成ですか？」

**4. 作業上の注意点**
- 「Claudeに特に注意してほしいことはありますか？（例：触ってはいけないファイル、特殊なワークフロー、よくあるミスなど）」
- 深掘り例：
  - 「自動生成されるファイルや直接編集してはいけないファイルはありますか？」
  - 「デプロイや本番環境に関して気をつけることはありますか？」
  - 「コミット・PRのルールはありますか？」
  - 「チームで使う場合、共有しておくべき暗黙のルールはありますか？」

**5. コメント・コミットメッセージの言語**
- 「コードのコメントやコミットメッセージは日本語・英語どちらで書きますか？」
- 深掘り：「PRタイトルや説明文は？ドキュメントは？」

### インタビューのコツ

- 事前調査で推測できた内容は積極的に確認として提示し、ユーザーの負担を減らす
- 「他に何かありますか？」と聞いて見落としを防ぐ
- 曖昧な回答（「特になし」「普通に」など）には「例えば〇〇のようなことですか？」と具体例を出して引き出す
- 必要十分な情報が集まったと判断したらインタビューを終了する

## フェーズ3: CLAUDE.md の生成

収集した情報をもとに、以下のテンプレートに従って `CLAUDE.md` を生成する。

### テンプレート

```markdown
# CLAUDE.md

このファイルは Claude Code がこのリポジトリで作業する際のガイドラインです。

## プロジェクト概要

{プロジェクト名}。{プロジェクトの概要・目的・主なユーザーを2〜3文で記述}

## 技術スタック

{主要な言語・フレームワーク・ライブラリをリスト形式で記述。外部サービスやDBも含める}

## 作業上の注意

{Claudeに注意してほしいことを箇条書きで記述。なければこのセクションは省略}

## 規約

{コメント・コミットメッセージ・PRの言語や命名規則などを記述}

## 詳細ドキュメント

詳細は以下を参照（必要に応じて記入してください）：

- `.claude/CONVENTIONS.md` — コーディング規約・命名規則
- `.claude/STRUCTURE.md` — ディレクトリ構成と各ディレクトリの役割
- `.claude/ARCHITECTURE.md` — アーキテクチャ・設計方針
```

### 生成ルール

- 300行以内に収める
- 情報がない・不要なセクションは省略する（無理に埋めない）
- 箇条書きを積極的に使い、読みやすくする
- 「特になし」のような無意味な記述は入れない

---

## フェーズ4: 詳細ファイルの生成

以下のファイルをプレースホルダーとして生成する。

```
.claude/
  CONVENTIONS.md
  STRUCTURE.md
  ARCHITECTURE.md
```

各ファイルの内容（共通フォーマット）：

```markdown
# {ファイルタイトル}

<!-- このファイルは setup-claude-md スキルによって生成されました -->
<!-- プロジェクトに合わせて内容を記入してください -->
```

`.claude/` ディレクトリが存在しない場合は作成する。

---

## フェーズ5: 完了アナウンス

生成完了後、以下をユーザーに伝える：

1. 生成されたファイルの一覧
2. 詳細ファイルへの記入を促すメッセージ：
   ```
   以下のファイルは空の状態で作成しました。必要に応じて内容を記入してください：
   - .claude/CONVENTIONS.md — コーディング規約・命名規則
   - .claude/STRUCTURE.md — ディレクトリ構成
   - .claude/ARCHITECTURE.md — アーキテクチャ・設計方針
   ```
3. 「CLAUDE.mdの内容を修正したい場合はお知らせください」と伝える
