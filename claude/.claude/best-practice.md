新しい学習を追加した際はこのファイルも更新してください。

## CLAUDE.md の設計原則

- **書くべきもの**: Claudeが推測できないコマンド・非標準のコードスタイル・ブランチ命名規則・環境の特殊事情
- **書かないべきもの**: Claudeが読めば分かるアーキテクチャ・頻繁に変わる情報・「きれいなコードを書く」など自明なこと
- **理想サイズ**: 約200行以内。それ以上は `.claude/rules/*.md` に分割
- **重要な原則**: CLAUDE.md はアドバイス（遵守率 ~80%）。**必ず実行させたいことはフックへ**（100%確実）
- **階層構造**: `~/.claude/CLAUDE.md`（全プロジェクト共通）→ `プロジェクト/CLAUDE.md`（チーム共有）→ `.claude/rules/*.md`（条件付きルール）

## .claude/ ディレクトリの理想構成

```
.claude/
├── settings.json          # パーミッション・フック設定（Gitにコミット）
├── settings.local.json    # 個人用オーバーライド（.gitignore必須）
├── .mcp.json              # MCP サーバー設定
├── rules/                 # CLAUDE.mdが肥大化したら分割する場所
└── skills/                # プロジェクト固有スキル
```

## Hooks の使い分け

| ハンドラー | 用途 |
|---|---|
| `command` | 基本。フォーマット・ブロック・ログなど決定論的な処理 |
| `http` | 外部サービスとの連携 |
| `prompt` | LLMのYes/No判断が必要なシンプルな検証 |
| `agent` | ファイル読み込み＋コマンド実行など複雑な検証（最重い） |

**主要イベント**: `PreToolUse`（ブロック可）・`PostToolUse`・`Stop`（ブロック可）・`SessionStart`

**すぐ使える実践例**:
- ファイル編集後に自動フォーマット（PostToolUse × Edit|Write）
- 作業完了時にmacOS通知（Stop × osascript）
- .envファイルへの書き込みをブロック（PreToolUse × Write|Edit）

## スキル設計のポイント

- `description` が自動呼び出しの精度を決める最重要フィールド
- キーワードを豊富に含め「〇〇と言ったときは必ずこのスキルを使う」と明示する
- `context: fork` でサブエージェント分離実行が可能
- `disable-model-invocation: true` で手動呼び出し専用にできる

## コンテキスト管理

| コマンド | 効果 |
|---|---|
| `/clear` | タスク切替時に履歴をリセット |
| `/compact` | 要約して同じタスクを継続 |
| `/memory` | 何が読み込まれているか確認 |
